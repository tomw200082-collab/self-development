# Self Development

מערכת אישית להתפתחות, רפלקציה ולמידה לאורך זמן.

הריפו התחיל סביב תהליך המנטורינג של **"אחים על מלא"**, אבל הוא בנוי מראש כך שיוכל להמשיך ללוות את טום גם אחרי התוכנית — כמערכת עבודה אישית שאפשר לפתוח בעתיד ישירות כ־Obsidian Vault.

## עקרונות

- Markdown נקי ופשוט.
- מעט מבנה, הרבה שימוש אמיתי.
- תובנות צריכות להפוך להחלטות, ניסויים או שינוי התנהגותי.
- מפרידים בין עובדה, פרשנות והשערה.
- לא מקבעים זהות או מטרות; מעדכנים כשמתגלות ראיות חדשות.
- המערכת נועדה לתמוך בחיים עצמם, לא להפוך לפרויקט תחזוקה.

## מבנה

- `00-system/` — הוראות ומנוע העבודה הקבועים.
- `01-state/` — תמונת המצב החיה והכיוונים הפעילים.
- `02-mentoring/` — תיעוד מפגשי מנטורינג.
- `03-reflections/` — רפלקציות משמעותיות מחוץ למפגשים.
- `04-experiments/` — ניסויים התנהגותיים ולמידה מהם.
- `90-templates/` — תבניות דקות לשימוש שוטף.

## איך עובדים עכשיו

1. לפני מפגש עם אביגדור — פותחים note חדש מתוך `90-templates/mentoring-session.md` וממלאים רק את חלק ה־Prepare.
2. אחרי המפגש — משלימים באותו קובץ את ה־Debrief.
3. מעדכנים את `01-state/MENTORING_STATE.md` רק במה שישפיע על שיחות והחלטות עתידיות.
4. אם עולה דפוס או שינוי התנהגותי ששווה לבדוק — יוצרים ניסוי קטן מתוך `90-templates/experiment.md`.
5. רפלקציות משמעותיות שלא קשורות ישירות למפגש נשמרות ב־`03-reflections/`.

## Obsidian בעתיד

אפשר יהיה לשכפל את הריפו למחשב ולפתוח את תיקיית השורש כ־Vault. המבנה כבר משתמש בקבצי Markdown וב־YAML frontmatter בסיסי, ולכן אין תלות ב־plugin מסוים.

מומלץ לאפשר ל־Obsidian ליצור את תיקיית `.obsidian/` מקומית; קבצי workspace אישיים יישארו מחוץ ל־Git לפי `.gitignore`.

## מקור האמת

- שיטת העבודה: `00-system/MENTORING_SKILL.md`
- הוראות הפרויקט: `00-system/PROJECT_INSTRUCTIONS.md`
- המצב הנוכחי: `01-state/MENTORING_STATE.md`

המטרה של הריפו היא לא לתעד הכול. שומרים רק חומר שעוזר **להבין טוב יותר, לבחור טוב יותר או לפעול טוב יותר**.
